# AnimaXS

A SwiftUI iOS app that runs the **Anima Turbo** text-to-image diffusion model
on-device (targeted at iPhone XS Max / A12) using Metal. It streamed-loads
quantized (W4/W8) model packs in the `.animapk` format and runs the full
pipeline — Qwen3 text encoder → LLM adapter → 28-block Anima DiT (8 Euler
steps) → Qwen-Image VAE — without a server.

## Requirements

- **macOS** with **Xcode 26.3** (project generated by XcodeGen 2.46.0).
- **iOS 18.0+ deployment target**, built with the iOS SDK shipped with Xcode.
  (The deployment target is the minimum OS the app can run on; the SDK used to
  *build* is independent of it. Signing is still required to install on your
  own iPhone.)
- **Physical target: iPhone XS Max** (A12 / Apple5 GPU). The app is validated
  functionally on a Metal-capable simulator, but memory/thermal/jetsam
  behaviour is only provable on the real device.
- The three model packs (~2.1 GB total) obtained through the in-app
  **Download** action or **Import** (see Models below).

> **Validation note:** GitHub Actions CI validates the code, the pack
> download/verify path, and functional Metal inference on a simulator. A
> physical iPhone XS Max has been used once (2026-08-15): it exposed bugs that
> CI could not catch (Files import permissions, silent Generate no-op, a
> Diagnostics crash, launch-time re-hashing). The repository-side fixes are
> implemented, but **A12 acceptance remains pending the physical retest** —
> performance, memory, jetsam, and thermal behaviour are not yet measured on
> the real device. See `DEVICE_TESTS.md`. Note also: `ModelStoreTests` uses
> synthetic downloader data; green CI does not prove the real GitHub
> production download route end-to-end (endpoint reachability + sizes were
> spot-checked 2026-08-15).

## Clone / open / build

1. Clone and open the committed Xcode project (no source edits required):

   ```bash
   git clone https://github.com/invisiblestrangler/AnimaXS.git
   cd AnimaXS
   open AnimaXS.xcodeproj
   ```

   (If you regenerate the project instead, use XcodeGen 2.46.0:
   `xcodegen generate`.)
2. In Xcode, select the **AnimaXS** scheme.
3. In **Signing & Capabilities**, select your Apple Development team. The
   project is configured for automatic signing; no development team is
   committed so that a clean clone builds anywhere.
4. Connect your **iPhone XS Max**, select it as the run destination.
5. Build and run (⌘R).

## Models

The app needs three `.animapk` packs. They are available as a **non-commercial**
release (`model-assets-v1`) and can be obtained two ways:

- **Download through the app** (recommended): on the Models screen, tap
  **Download** for each of the three packs. The app downloads, verifies the
  exact byte size and SHA-256 against its built-in manifest, and atomically
  installs each pack into Application Support. A corrupt or wrong-size file is
  rejected; **Retry/Repair** reinstalls it.
- **Import** (equivalent verification): if you have the pack files already
  (e.g. you converted them yourself), tap **Import** and select each `.animapk`.
  Imported files go through the same size + SHA-256 verification as downloads
  and are rejected if they do not match the manifest.

Expected filenames (from `ModelManifest`):

```
anima-turbo-v1.0-xsmax-w4.animapk      (DiT + adapter; serves both)
qwen3-0.6b-xsmax-w8.animapk            (text encoder)
qwen-image-vae-xsmax-fp16.animapk      (VAE)
```

After a verified install (Download/Import/Repair), the app persists a small
verification receipt. Normal launches trust installed packs with cheap
stat/metadata checks — they do **not** re-hash the ~2.07 GB set. A missing or
stale receipt triggers one full off-main SHA-256 verification (the migration
path for packs installed by older builds). Model discovery is local-only and
never downloads; only explicit **Download**/**Retry**/**Repair**/**Import**
actions touch the network or write model files.

Generation is disabled until all three packs are verified `ready`; the UI
shows the exact reason whenever Generate cannot start.

## Generation

- **Prompt** — editable text field (nonempty required).
- **Seed** — numeric seed; it feeds the production RNG (`SeededRNG`) that
  creates the initial latent. Same prompt + same seed + same models → same
  image.
- **Randomize** — generates a new seed and updates the visible field.
- **Generate** — runs one production generation: tokenize → Qwen → adapter →
  8-step DiT → VAE → image.
- **Cancel** — cooperatively stops at the next safe diffusion block boundary,
  preserving the last completed step for Resume.
- **Resume** — if a compatible checkpoint exists (e.g. after Cancel or moving
  to the background), shows the completed step count and continues diffusion
  from there.
- **Progress** — shows stage, diffusion step (1–8), block (1–28), and elapsed
  time.
- **Share** — exports the generated PNG via the system share sheet.
- **Diagnostics** — opening the screen collects a cheap snapshot (device
  facts, model presence/size/receipt state — no hashing). Explicit buttons run
  basic self-tests (W4/W8 decode, RNG, small file read, Metal capability),
  hardware tests (MPS precision, GEMM, attention tile — sequential, with
  per-test progress and a recorded current-test marker so a native crash can
  be localized on the next launch), and an opt-in deep SHA-256 of all packs
  (~2.07 GB read). JSON export serializes the current report and runs zero
  tests.

## Limitations

- GitHub Actions validates the build and functional Metal inference on a
  simulator, **not** physical A12 behaviour. A first physical-device run
  (2026-08-15) found and fixed import/download/diagnostics/launch issues, but
  A12 memory, thermal, and performance characteristics are still pending the
  device retest (see `DEVICE_TESTS.md`).
- VAE tiling is intentionally **not** implemented yet; it will only be added if
  full-frame decoding fails on-device due to memory/timeout pressure (and must
  then preserve convolution halos and global spatial attention).
