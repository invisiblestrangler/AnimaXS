## Parsing / format (validated against real packs 2026-08-10)
- **D008: Real packs have `json_offset=256` and `table_offset=327936` — NOT 16 KB aligned** (only `payload_offset` and every `blob_offset` are). ANIMAPK_SPEC.md's "all sections 16 KB aligned" claim is inaccurate. Parser enforces blob alignment (the real invariant) but NOT section alignment.
- **D009: Architecture JSON `component` is a string** (`"dit"`/`"te"`/`"vae"`), not an integer code. The integer code 1/2/3 lives only in the 256-byte binary header.
- **D010: TE layers are ALSO physically string-sorted** (`0,1,10..19,2,20..27,3..9`), exactly like DiT blocks — HANDOFF.md's "layers 0-27 in order" is misleading. Each TE layer spans a contiguous 16,777,216 B range, but layer N's location MUST come from metadata lookup, never arithmetic. Same rule as DiT block ranges.
- **D011: Every tensor blob (all 1,189 across 3 packs) verified 16 KB aligned and CRC-32 clean** (0 mismatches) by the Swift parser. W4/W8 known vectors byte-exact vs HANDOFF.md §12–§13.
- **D012: DiT physical block order confirmed** = `0,1,10..19,2,20..27,3..9` (string sort). Each block's 20 tensors are contiguous and span exactly 38,993,920 B; adjacent blocks tile without gaps.
- **D013: `TestPackFactory` (synthetic ANMA v1 writer) uses a FIXED region layout** mirroring real packs: JSON at 256, table at 16 KB, payload after. This avoids JSON-size/offset circular dependency and keeps synthetic tests free of multi-GB assets. (Iteration note: `Data._Representation.init(count:)` aborts on negative counts — guard all padding arithmetic.)

## Tokenizer parity (validated against goldens 2026-08-10)
- **D014: Tokenizer parity rule (VALIDATED against case1/2/3 seed1337 goldens):**
  - **Qwen** (Qwen2Tokenizer, qwen25_tokenizer/ vocab.json+merges.txt): `encode(prompt, add_special_tokens=False)` — NO start/end token, NO trailing token. Produces EXACTLY the golden `cond_context` sequence lengths (46/72/122).
  - **T5** (T5TokenizerFast, t5_tokenizer/ tokenizer.json): `encode(prompt, no_specials)` **+ one trailing `</s>` (id 1)**. The reference appends a T5 EOS. Golden has exactly prompt_len+1 T5 IDs (47/85/134).
  - Source: `comfy/text_encoders/anima.py` (Qwen3Tokenizer/T5XXLTokenizer) + golden cross-check.
- **D015: Tokenizer assets bundled as app resources** (`Resources/Tokenizers/qwen`, `/t5`, ~6.7 MB) — loaded locally by swift-transformers `Tokenizers`; no HF network at runtime. Assets copied from `comfy/text_encoders/qwen25_tokenizer` + `t5_tokenizer`.
- **D016: Tokenization done via Python `transformers` oracle** (`scripts/gen_tokenizer_ref.py`) → fixture `Fixtures/tokenizer_reference_ids.json`. Swift must match exactly; v1 rejects prompts >512 tokens (Qwen or T5) instead of truncating (runbook §16).
- **D017: `QuantDecoders` are Data-based** (not UnsafeRawBufferPointer) — scopes `withUnsafeBytes` internally. Passing `withUnsafeBytes{ $0.baseAddress }` results across closures is a dangling-pointer bug that silently returns garbage/0 for small Data; the mmap-backed real-pack path masked it. This is a pitfall for all future Metal/CPU buffer code.

## Qwen encoder parity (RESOLVED 2026-08-10)
- **D018: Qwen GQA grouping is grouped-repeat, not modulo.** Pinned ComfyUI `comfy/ops.repeat_kv_for_gqa` expands K/V heads via `repeat_interleave(n_rep=2, dim=head_dim)` → contiguous grouped heads `[K0,K0,K1,K1,...,K7,K7]`. Correct Q→KV mapping is `kvHead = queryHead / (queryHeads/kvHeads) = queryHead / 2` for Qwen3-0.6B (16/8). The previous `kvHead = queryHead % 8` (round-robin) was WRONG and scrambled which V-vector each Q head reads (full-28 cosine vs golden −0.04). Fixed both in `QwenEncoderCPU.swift` (app + harness). Regression test `GqaHeadMappingTests`.
- **D019: `cond_context` INCLUDES the final RMSNorm.** `Qwen3_06BConfig.final_norm=True` (llama.py:130); `SDClipModel` with `layer=="last"` returns the main output AFTER `x = self.norm(x)` (llama.py:800-801). `layer_norm_hidden_state=False` in anima.py only suppresses final norm on the *intermediate* path, not the main output. HANDOFF.json's "NO final norm" note is wrong about the capture point. Golden matches post-final-norm (cosine 0.992) vs pre-final-norm (0.62). Swift encoder now applies `model.norm.weight` RMSNorm in `encode()`.
- **D020: Qwen encoder kernel is structurally CORRECT (validated).** Built `scripts/qwen_comfy_oracle.py` (transcribes pinned ComfyUI equations verbatim with line citations; dequantizes same W8 animapk via inspect_animapk). Swift W8 == pinned-Comfy W8: cosine 1.000000, maxAbs 0.0004. Swift W8 vs golden: cosine 0.992164 (W8-vs-bf16 quantization deviation, comparison B). Per GOLDENS.md §5 cosine ≥ 0.99 boundary → kernel correct. Per-layer oracle fixtures at `scripts/oracle_out/qwen_oracle_layers.npz`.

## LLM adapter (RESOLVED 2026-08-10)
- **D021: Adapter math resolved from pinned source `comfy/ldm/anima/model.py` (commit cbbc9da), not handoff guess.** MLP activation = **exact GELU** (`nn.GELU()`, default approx='none'; NOT SiLU). **Self-attn = MHA 16/16 bidirectional** (no causal mask; `target_attention_mask=None` in case1 — all attend). **Cross-attn = MHA 16/16 over Qwen context** (query_dim=model_dim=1024, context_dim=source_dim=1024; `source_attention_mask=None`). **RoPE** = `apply_rotary_pos_emb` with `rotate_half` (model.py:13-17), `rope_theta=10000`, head_dim=64, applied to Q & K of BOTH self and cross attn. NOTE: for a single head, interleaved `rotate_half` and Qwen3's half-split are numerically EQUIVALENT per-position (same rotation; only the pairing convention differs) — verified maxAbs diff 0.0; do not write a test asserting they differ. **Norm order**: RMSNorm(eps 1e-6) before self_attn, cross_attn, and MLP; final RMSNorm after out_proj. **Biases**: out_proj + MLP (`mlp.0`/`mlp.2`) carry bias (default nn.Linear); attn q/k/v/o projections have `bias=False` (no bias). in_proj is Identity (model_dim==target_dim==1024). RotaryEmbedding.forward forces float32 for freqs.
- **D022: LLMAdapter structurally validated.** Built `scripts/anima_adapter_oracle.py` (transcribes pinned LLMAdapter math; dequantizes same W4 DiT pack `model.diffusion_model.llm_adapter.*`). Swift == oracle (same W4 weights): weighted [1,47,1024] cosine **1.000000** (rmse 5.2e-7, maxAbs 3.3e-6); padded [1,512,1024] cosine 1.000000, tail all-zero, finite. Adapter conditioning is fully deterministic from cond_context + T5 ids (GOLDENS.md §3) — the golden captures pre-adapter context; final correctness validated at DiT stage. Regression tests `LLMAdapterTests` (interleaved RoPE, exact GELU).

## DiT input + timestep (RESOLVED 2026-08-10)
- **D023: DiT input patchify order = (c·4 + m·2 + n), padding-mask channel 16 = zeros.** `PatchEmbed` (predict2.py:299-309) uses einops `"b c (t r) (h m) (w n) -> b t h w (c r m n)"` with r=1 (patch_temporal), m=n=2 (patch_spatial). For T=1 the r term is always 0, so the 68-wide last-dim feature index is `c·(2·2) + m·2 + n` (c outermost). The padding-mask channel is appended as zeros (predict2.py:808) when `concat_padding_mask=True`, giving 17 effective channels. x_embedder Linear(68→2048) has NO bias. Weight: `model.diffusion_model.x_embedder.proj.1.weight` [2048,68] W4 (index 1 = the Linear inside `nn.Sequential(Rearrange, Linear)`).
- **D024: DiT timestep embedder — sigma→sinusoidal, then adaln path; embedding = RMSNorm(raw).** `t_embedder = Sequential(Timesteps(2048), TimestepEmbedding(2048,2048,use_adaln_lora=True))` (predict2.py:698-701). Timesteps (219-238): half_dim=1024, `emb = sigma·exp(-log(10000)·arange(1024)/1024)`, `out = cat([cos(emb), sin(emb)])` → cos in [0:1024], sin in [1024:2048]. TimestepEmbedding (257-269) with use_adaln_lora=True: `adaln_lora_B_T_3D = Linear2(SiLU(Linear1(raw)))` [6144], `emb_B_T_D = raw` (the sample itself). Then `t_embedding_B_T_D = RMSNorm(raw)` (predict2.py:882). Weights: `t_embedder.1.linear_1.weight` [2048,2048] W4, `t_embedder.1.linear_2.weight` [6144,2048] W4, `t_embedding_norm.weight` [2048] fp16.
- **D025: DiT input/timestep structurally validated.** Built `scripts/dit_input_timestep_oracle.py` (transcribes predict2.py PatchEmbed/Timesteps/TimestepEmbedding and reads W4-dequantized harness dumps). With the corrected row-aware decoder from D034, Swift x_embedder [1024,2048] still matches the independent matmul at cosine **1.000000000** (maxAbs `3.58e-7`, all finite). Timestep raw sinusoid, RMSNorm embedding [2048], and adaln_lora [6144] each match at cosine **1.00000000** (adaln maxAbs `9.9e-5`). CPU tests lock patchify ordering and sinusoidal references. The original same-dump H001 check did not validate dequantization itself and therefore could not expose the 68-column row-reset bug; D034’s decoder regressions close that gap.

## AdaLN-LoRA modulation (RESOLVED 2026-08-10)
- **D026: AdaLN modulation applies SiLU to emb_B_T_D BEFORE Linear1 — the handoff §8 prose was WRONG.** `Block.__init__` (predict2.py:451-465) builds each branch as `nn.Sequential(nn.SiLU(), Linear(x_dim→adaln_lora_dim, no bias), Linear(adaln_lora_dim→3·x_dim, no bias))`. `nn.Sequential` applies modules in order, so `mod_branch = Linear2( Linear1( SiLU( emb_B_T_D ) ) )`, then `mod = mod_branch + adaln_lora_B_T_3D` (predict2.py:488), then `shift, scale, gate = mod.chunk(3, dim=-1)` (shift=[0:2048], scale=[2048:4096], gate=[4096:6144]). The handoff §8 and MODEL_ARCHITECTURE.json `adaln_modulation` string claim `SiLU(Linear(2048→256)(emb))` (Linear1 before SiLU) — that is INCORRECT; the pinned source is authoritative and puts SiLU first. My initial numpy oracle transcription copied the handoff order and gave cosine ~0.44-0.99; correcting to SiLU-first gives cosine **1.00000000**. Weights: `blocks.N.adaln_modulation_{self_attn,cross_attn,mlp}.{1,2}.weight` ([256,2048] and [6144,256], both W4).
- **D027: Block modulation uses LayerNorm (elementwise_affine=False, mean-CENTERING), not RMSNorm.** `Block.__init__` (predict2.py:438,441,446) uses `operations.LayerNorm(x_dim, elementwise_affine=False, eps=1e-6)` for self_attn/cross_attn/mlp. Applied in `_fn` (predict2.py:520-521): `normalized = LayerNorm(x) * (1 + scale) + shift`. This mean-centers (subtracts mean) — distinct from the Qwen/DiT RMSNorm paths. The residual-add is `torch.addcmul(x, gate, branch_out)` = `x + gate*branch_out` (predict2.py:542,575,590). fp32 throughout.
- **D028: AdaLN-LoRA modulation structurally validated.** `Modulation.swift` + oracle (same script, `scripts/dit_input_timestep_oracle.py`): block-0 shift/scale/gate for all 3 branches cosine **1.00000000** (maxAbs ~3e-5, all finite). CPU tests `ModulationTests` (LayerNorm constant-input==shift, mean-centering, SiLU).
- **D029: DiT 3-D RoPE — exact thetas, freq order, block layout, and structural validation.** RoPE is **weightless** (no pack tensors) — the `[1024,64,2,2]` basis is computed purely from the grid dims. Transcribed VERBATIM from `comfy/ldm/cosmos/position_embedding.py` `VideoRopePosition3DEmb` (57-163). Thetas are **computed exactly** `h_theta = w_theta = 10000.0 * 4.0**(42.0/40.0) = 42870.938501451725` (Float32 → 42870.938) and `t_theta = 10000.0` — the prose 42871.1/42871.4 (handoff §7 / MODEL_ARCHITECTURE.json / RUNBOOK §31) are all rounded approximations; trust position_embedding.py:127-129 (another "pinned computation > prose", like D026). Dim split 42/42/44 → numFreqs = 22 (temporal) + 21 (h) + 21 (w) = 64 2×2 blocks per 128 head-dim. **Freq concat order is t,h,w** (position_embedding.py:154-161) → blocks [0..22)=temporal, [22..43)=height, [43..64)=width. Each block is `[cos,-sin,sin,cos]` (150-152). Applied to self-attention only. Built `scripts/dit_rope_oracle.py` (independent numpy re-transcription). Swift `DitRoPE.generate(T:1,H:32,W:32)` == oracle: shape [1024,64,2,2] exact, cosine **1.000000000** (maxAbs 4.77e-7, all finite). CPU tests `DitRoPETests` (config, exact thetas, shape/finite, t/h/w ordering, 2×2 layout, width/height rotations). Metal slice compare deferred to a later Metal task (weightless rope; CPU-vs-oracle cosine is the authoritative H004 gate per NEXT_TASK_HANDOFF §4).
- **D030: `rms_rope_split_half` pairs the two HALVES of the head dim — `(p, p+64)`, NOT adjacent `(2p, 2p+1)`.** This is the H005-critical detail for applying the H004 rope to self-attn Q/K. The `comfy.quant_ops.ck.rms_rope_split_half` implementation lives in the C++/CuTe `comfy_kitchen` backend (not in the frozen repo as plain Python, and not importable here), but the **frozen local repo has a pure-Python reference for the exact same split-half family**: `comfy/ldm/ideogram4/model.py` `_apply_rope_split_half1` (40-44) + `_split_half_rope_matrix` (31-37) — the training-mode path for the identical `rms_rope_split_half` call (ideogram4/model.py:70). `x.reshape(...,2,-1).movedim(-2,-1)` on a 128-d head splits `[x0..x127]` into `[[x0..x63],[x64..x127]]` → 64 vectors `(x0,x64),(x1,x65),...,(x63,x127)`. Matrix `[[cos,-sin],[sin,cos]]` applied as `out[p]=c·a−s·b, out[p+64]=s·a+c·b` (a=x[p], b=x[p+64]). Per-token-per-head RMSNorm(128) runs FIRST with one SHARED [128] q_norm weight (and shared [128] k_norm) across all 16 heads, eps 1e-6, no mean-subtraction, norm-before-rotate. This was confirmed by an advanced-AI consultation (the pairing risk is item #1 on the H005 failure list — using adjacent `(2p,2p+1)` would produce plausible-but-wrong attention). H004's `[1024,64,2,2]` rope tensor is unchanged — only the block→head-dim mapping changes (block p ↦ dims (p, p+64)).
- **D031: DiT Block.forward canonical inputs — extra_per_block_pos_emb = None, no attention mask, no DiT GQA.** Confirmed from pinned source + consultation: (a) `extra_per_block_abs_pos_emb` defaults **False** (predict2.py:657), so `extra_pos_emb = None` (predict2.py:818-821) and the `x += extra_per_block_pos_emb` path (predict2.py:483-484) is a no-op for Anima (pos_emb_cls="rope3d", no learnable per-block emb). (b) No attention mask: `torch_attention_op` → `optimized_attention(..., skip_reshape=True)` with no mask; self-attn is bidirectional (no causal mask). (c) **No DiT GQA**: 16 Q / 16 K / 16 V heads, all proj output 2048; `repeat_kv_for_gqa` never triggers (n_rep=1). (d) Cross-attn context is the full zero-padded adapter output `[1,512,1024]` passed unchanged to every block; the 465 zero-padded rows still participate in softmax (their K/V are exact 0 but the logits affect the denominator), so they MUST NOT be truncated. (e) Block residual stream is fp32; attention/MLP branch inputs are cast to `compute_dtype` (fp16 in the real model) via `.to(compute_dtype)` (predict2.py:532,556,582); the gate residual add is fp32 (`.to(residual_dtype)`, predict2.py:542,575,590). The block also promotes an fp16 residual to fp32 at the top (predict2.py:918-919). H005 gate: transcribe the math in FP32 first (Lane A: Swift==NumPy structural), then compare W4-fp32 vs golden `block_00_out` (Lane B, cosine ≥ 0.999), then optional fp16-boundary emulation only if Lane B needs diagnosis.

## DiT block 0 (H005)
- **D032: H005 canonical golden input is the final hook invocation (2026-08-11).** The frozen `trace_anima.py` overwrites `block_caps[idx]` on every sampling call, so `block_00_out` is from sampler step 7 at sigma `0.3050089478492737`, not step 0. `scripts/dit_block0_oracle.py --golden-step 7` reconstructed an input from `init_noise_randn` and the then-assumed denoised callback arrays and matched `/root/anima-harness/block0_latent_step7.f32`; that harness file came from the same reconstruction path, so the match was not independent evidence of callback semantics. D055 supersedes that semantic claim after checking the recorded arrays against the unavoidable final Euler invariant. H005's same-input Swift/NumPy/source block-graph result remains valid, but it must not be cited as proof that the legacy sampler trace is internally coherent.
- **D033: The old H005 `0.734523` result is superseded, not an accepted baseline (2026-08-11).** It came from an incorrectly dequantized `x_embedder` and must not be used for tolerance decisions. Optional fp16/bfloat16 boundary experiments performed before correcting that input were diagnostic only.
- **D034: Quantized matrix groups reset at every row (H005 root cause, 2026-08-11).** `pack_anima.py::quantize_matrix` calls `quantize_groupwise` independently for each `[out,in]` row. The prior Swift loaders flattened matrices and used `flatIndex / 64`, which shifts scale/zero indices whenever K is not divisible by 64. DiT `x_embedder.proj.1.weight [2048,68]` is the only source DiT rank-2 tensor with non-aligned K, explaining why decoder vectors and every other block matrix looked correct. `QuantDecoders.dequantW4Matrix`/`dequantW8Matrix` now index `group = row*ceil(K/64) + col/64`; all matrix loaders use them. Regression tests use 2×68 W4 and 2×65 W8 matrices and assert row-1 groups. The corrected W4 x-embed matmul independently matches Swift at cosine `1.000000000` (maxAbs `3.58e-7`).
- **D035: H005 is green under the guidance's source-proven tolerance exception (2026-08-11).** On the canonical step-7 input, corrected Swift-W4 vs independent memmap NumPy-W4 is cosine `1.000000000`, RMSE `6.18e-6`, maxAbs `1.91e-4`, all finite. NumPy-W4 vs original BF16 golden is cosine `0.998712106`, RMSE `9.43e-2`, maxAbs `1.79`, relative L2 `5.074073e-2`; Swift-W4 reproduces it at cosine `0.998712139`, relative L2 `5.074009e-2`. To separate graph correctness from quantization, the official source safetensors identified by pack hash `c0b905034510750a505d21aa96c81718f4ffcc500777318421f58a88636e2174` was range-read and block 0 executed with original BF16 tensors: cosine vs golden `0.999992303`, RMSE `7.31e-3`, maxAbs `0.442`, relative L2 `3.93489e-3`. The corrected W4 x-embed output alone is cosine `0.998998606` vs source (`x_embedder` weights `0.997700486`). FP16 branch-boundary emulation leaves W4-vs-golden at `0.998712077`. This supplies the hard gate's required source-proven reason for the pack-vs-original tolerance to be slightly below `0.999`; proceed to the production Metal block-0 gate E009 without changing block math.

## Production Metal transition (2026-08-11 audit)

- **D036: H005 is a CPU correctness oracle, not authorization for a CPU full-DiT implementation.** `DiTBlockCPU` intentionally materializes dequantized Swift arrays and is useful for diagnosis/tests, but extending it over 28 blocks would violate the bounded-memory runtime design. Production order is D007 zero-copy spans → E001–E008 Metal/MPS primitives → E009 production Metal block 0 parity → H006 streamed Metal 28-block loop. H006 now depends on E009.
- **D037: Standard hosted simulator CI is a functional Metal/MPS gate.** Initial probe `31450755207` and final permanent-test snapshot `31452206651` completed successfully on standard `macos-15` arm64: `MTLCreateSystemDefaultDevice()` returned `Apple iOS simulator GPU`; `dequant_w4_to_half` produced expected fp16 values; and a 2×2 `MPSMatrixMultiplication` produced the expected matrix. Therefore every pack-free Metal/MPS parity test runs in normal simulator CI. A12 performance, jetsam/memory, Apple5 behavior, watchdog, page cache, and thermal gates remain physical-device-only.
- **D038: Model distribution has a two-level license gate.** On 2026-08-11 the authoritative Anima page exposed CircleStone Non-Commercial License v1.2, including non-commercial/derivative distribution, license-copy, exact attribution, modification-disclosure, protective-disclaimer, and no-endorsement conditions. The Anima model card identifies the model as a derivative of NVIDIA Cosmos-Predict2-2B-Text2Image; that model's NVIDIA Open Model License (2025-04-30) requires its agreement/Notice attribution, “Built on NVIDIA Cosmos,” and other use conditions. Sources: `https://huggingface.co/circlestone-labs/Anima/blob/main/LICENSE.md` and `https://huggingface.co/nvidia/Cosmos-Predict2-2B-Text2Image/blob/main/README.md`. A005 must archive and evaluate both exact current sources before any `.animapk` release. No pack upload is authorized by this summary alone.
- **D039: Precision-sensitive Metal semantics are fixed by H005.** E003/E004 must use exact erf GELU, Float32 LayerNorm/RMSNorm statistics, Float32 modulation/gates/residual additions, and split-half DiT RoPE pairs `(p,p+64)`. The existing tanh GELU and half gate-add shader functions are scaffolding and cannot satisfy E003. E002/E005/E006 must preserve per-row group reset for non-aligned K.
- **D040: XcodeGen must omit empty directories.** `generateEmptyDirectories: false` is required because git does not preserve empty folders: a populated local checkout had empty `Runtime/DiT`, `VAE`, `ModelStore`, and `Sampler` directories, while a clean Actions checkout did not, producing a platform-dependent `.pbxproj` diff. Real source files create their groups automatically. Snapshot CI run `31451847376` caught this before compilation.
- **D041: CI pins XcodeGen 2.46.0 by official release zip and SHA-256.** An unused `XCODEGEN_VERSION=2.44.1` plus `brew install xcodegen` was not reproducible and generated Homebrew tap warnings. CI now downloads `xcodegen.zip` for 2.46.0, verifies SHA-256 `4d9e34b62172d645eed6457cac13fc222569974098ef4ee9c3368bedf0196806`, and uses that binary. Final snapshot run `31452206651` verified the checksum and clean regeneration. Update version, checksum, generated project, and a live consistency run together.
- **D042: Execution ranges are metadata-derived and one-slot-ring sized.** D007/D008 use exact numbered name prefixes, checked absolute arithmetic, and tensor data/scale/zero spans relative to each contiguous execution range. They never trust `block_index`, fixed block sizes, or physical JSON order. The real packs audit to DiT 28 blocks/560 tensors (maximum range 38,993,920 bytes) and Qwen 28 layers/308 layer tensors plus 151,936 independently addressable embedding rows. CI `31455204105` also proves E001 diagnostics and E002 W4 `[2,68]`/W8 `[2,65]` row-reset and padded 2-D bounds on hosted Metal.
- **D043: Apple5 exact-arithmetic implementation uses erf-form GELU and bounded threadgroup reductions.** Xcode 26.3's Apple5 Metal library does not expose `erf`, so E003 evaluates the source's exact GELU equation with the high-accuracy Numerical Recipes erf-form approximation; it is tested directly against Foundation `erf` and is not the removed tanh GELU approximation. RMSNorm/LayerNorm use one power-of-two threadgroup per row (maximum 256 threads), fp32 reductions, and fp16 packed weights where applicable. E004 fuses per-head RMSNorm with split-half `(p,p+64)` RoPE.
